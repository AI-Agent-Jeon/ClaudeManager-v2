## Preamble (사전 점검)

실행 전 다음을 확인한다:
1. DPL-001~004 존재 여부
   !`ls docs/deploy/ docs/releases/ 2>/dev/null`
2. 현재 브랜치 확인
   !`git branch --show-current`

누락 산출물이 있으면 Agent에게 보고하고 deploy 스킬 회귀를 제안한다.

## 입력 (이전 스킬에서 받는 바통)

- DPL-001 배포 체크리스트
- DPL-002 환경 설정 가이드
- DPL-003 릴리스 노트
- DPL-004 롤백 계획
- 운영 중 이슈/버그 보고

## 출력 (다음 스킬에 넘기는 바통)

- OPS-001 운영 매뉴얼
- OPS-002 버그 리포트
- OPS-003 패치 코드
- OPS-004 회귀 테스트 결과
- OPS-005 다음 Phase 피드백

## 필요 권한

- 도구: Read, Write, Edit, Bash, Grep, Glob
- Sub-Agent: dev-sub (버그 수정), test-sub (회귀 테스트)

## 절차

1. 증상 파악: 에러 메시지, 재현 조건 확인
2. 재현: 동일 환경에서 버그 재현
3. 원인 분석: 로그/코드 추적으로 근본 원인 식별
4. 가설 수립: 원인에 대한 가설을 세우고 검증
5. dev-sub에게 최소 범위 수정 위임
6. test-sub에게 회귀 테스트 실행 위임 (기존 테스트 + 재현 테스트)
7. 사용자 피드백 수집 및 정리
8. 다음 Phase 피드백으로 기록 (docs/feedback/)
9. 결과 보고

## 의사결정 포인트

- 핫픽스 배포: 대표 승인 필수 (높음)
- 다음 Phase 피드백 확정: 대표 확인 (보통)

## 체크포인트

- 원인 분석 완료 후 중간 보고
- 패치 + 회귀 테스트 완료 후 보고

## 제약 사항

- 원인 미확인 상태에서 "일단 수정"하지 않는다
- 수정 범위를 최소화한다 (관련 없는 리팩토링 금지)
- 재현 불가 시 대표에게 보고하고 판단 요청
- 핫픽스는 대표 승인 필요 (의사결정 등급: 높음)

## 완료 조건

- 설정된 관찰 기간 동안 치명/높음 장애 0건
- 운영 결과와 다음 Phase 피드백 기록 완료

## 실패/에스컬레이션 조건

- 재현 불가 시 대표에게 보고
- 동일 원인 3회 연속 실패 시 대표에게 에스컬레이션
- 긴급 장애 시 즉시 롤백 + 대표 보고

## 완료 후 액션

스킬 완료 시:
1. 완료 요약 (운영 결과 + 피드백)
2. docs/00-progress.md 갱신
3. 다음 Phase 제안: "다음 Phase 기획을 시작할까요?"
