## 입력 (이전 스킬에서 받는 바통)

- 대표 요청 (신규 Phase)
- OPS-005 다음 Phase 피드백 (후속 Phase)

## 출력 (다음 스킬에 넘기는 바통)

- PLN-001 요구사항 정의서
- PLN-002 Phase 계획서
- PLN-003 우선순위 목록
- PLN-004 용어 사전
- PLN-005 프로젝트 코드 체계

## 필요 권한

- 도구: Read, AskUserQuestion
- Sub-Agent: 없음

## 절차

1. 요구사항 수집: 대표의 요청을 구조화된 형식으로 정리
2. 기존 요구사항 정의서(docs/requirements/) 확인
3. 이전 Phase 피드백(docs/feedback/) 확인 및 반영
4. 사용자 스토리 작성: 역할-기능-이유 형식
5. 우선순위 결정: 필수/선택/향후로 분류
6. Phase 범위 확정: 이번 Phase에서 구현할 기능 목록
7. Phase 계획서 작성: 작업 목록, 순서, 산출물 정의
8. 대표에게 보고하고 승인 요청

## 의사결정 포인트

- Phase 범위 확정: 대표 승인 필수 (높음)
- 우선순위 결정: 대표 승인 필수 (높음)

## 체크포인트

- 요구사항 수집 완료 후 중간 보고
- Phase 계획서 초안 작성 후 검토 요청

## 제약 사항

- Phase 계획은 반드시 대표 승인 후 실행 (의사결정 등급: 높음)
- 미결정 사항은 명시적으로 표시
- 이전 Phase 운영 피드백이 있으면 반드시 반영
- 기존 요구사항을 반복 작성하지 않고 버전/변경 이력으로 연결

## 완료 조건

- 대표 승인
- 수용 기준 포함 여부 확인

## 실패/에스컬레이션 조건

- 요구사항 간 상충 발견 시 대표에게 보고
- 기술적 실현 불가 판단 시 대표에게 에스컬레이션
