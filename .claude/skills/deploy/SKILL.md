## Preamble (사전 점검)

실행 전 다음을 확인한다:
1. TST 전체 통과, PR 머지 확인
   !`gh pr list --state merged --limit 5 2>/dev/null`
2. 현재 브랜치 확인
   !`git branch --show-current`

누락 산출물이 있으면 Agent에게 보고하고 test 스킬 회귀를 제안한다.

## 입력 (이전 스킬에서 받는 바통)

- TST 전체 통과 확인
- DEV-003 PR 머지 완료

## 출력 (다음 스킬에 넘기는 바통)

- DPL-001 배포 체크리스트
- DPL-002 환경 설정 가이드
- DPL-003 릴리스 노트
- DPL-004 롤백 계획

## 필요 권한

- 도구: Read, Bash (빌드/배포)
- Sub-Agent: 없음

## 절차

1. 배포 전 확인: 테스트 결과 리포트에서 치명/높음 결함 0건 확인
2. 배포 체크리스트 작성: 환경 변수, 의존성, 마이그레이션 확인 (자동)
3. 빌드 실행 (자동)
4. 사전 검증: 스모크 테스트 (자동)
5. 대표에게 배포 승인 요청 (실제 환경 변경 직전)
6. 배포 실행
7. 배포 후 모니터링
8. 릴리스 노트 작성
9. 배포 완료 보고

## 의사결정 포인트

- 실제 환경 배포 실행: 대표 승인 필수 (높음)
- 롤백 실행: 긴급 시 자동, 그 외 대표 승인

## 체크포인트

- 빌드 성공 후
- 스모크 테스트 통과 후 (배포 승인 요청 전)

## 제약 사항

- 배포 준비/체크리스트/빌드는 자동 수행
- 실제 환경 배포 실행만 대표 승인 필수 (의사결정 등급: 높음)
- 테스트 미통과 상태에서 배포하지 않는다
- 롤백 계획을 배포 전에 준비한다
- 배포 후 모니터링 시간은 프로젝트 설정값에 따른다

## 완료 조건

- 대표 승인 후 배포 실행 완료
- 스모크 테스트 통과

## 실패/에스컬레이션 조건

- 빌드 실패 시 develop 스킬로 회귀
- 배포 후 장애 발생 시 롤백 실행 + 대표 보고

## 완료 후 액션

스킬 완료 시:
1. 완료 요약 (배포 결과 + 릴리스 노트)
2. docs/00-progress.md 갱신
3. 스킬 전환 모드 확인 → 자동이면 operate 스킬 시작, 승인이면 대표에게 제안
