## 입력 (이전 스킬에서 받는 바통)

- ANL-001 분석 보고서
- ANL-002 의존관계 맵
- ANL-003 리스크 목록
- ANL-004 기술 스택 결정서

## 출력 (다음 스킬에 넘기는 바통)

- DES-001 아키텍처 설계서
- DES-002 API 명세서
- DES-003 데이터 모델 (ERD)
- DES-004 와이어프레임
- DES-005 스토리보드
- DES-006 화면 명세서
- DES-007 상태 흐름도
- DES-008 파일/디렉토리 구조
- DES-009 코드 정의서 (시스템)

## 필요 권한

- 도구: Read, Write (docs/ 전용), Grep, Glob
- Sub-Agent: docs-sub (문서 작성)

## 절차

1. 분석 보고서와 의존관계 맵 읽기
2. 아키텍처 설계: 모듈 구조, 레이어, 의존 방향
3. API 설계: 엔드포인트, 요청/응답 형식
4. 데이터 모델 설계: 엔티티, 관계, 스키마
5. 와이어프레임: UI 레이아웃, 화면 구성
6. 스토리보드: 사용자 흐름 (화면 간 네비게이션)
7. 화면 명세서: 각 화면의 상세 동작, 상태, 유효성 검사
8. 상태 흐름도: 에이전트 상태 전이 정의
9. 파일/디렉토리 구조 결정
10. 코드 정의서: 시스템 코드/Enum 정의
11. docs-sub에게 설계 문서 작성 위임
12. 대표에게 보고하고 승인 요청

## 의사결정 포인트

- 아키텍처 설계 확정: 대표 승인 필수 (높음)
- UI/UX 설계 확정: 대표 승인 필수 (높음)

## 체크포인트

- 아키텍처 설계 완료 후 중간 보고
- 와이어프레임 완성 후 검토 요청

## 제약 사항

- 분석 단계에서 식별한 리스크에 대한 대응책 포함
- 설계는 반드시 대표 승인 후 개발 진행 (의사결정 등급: 높음)
- 코딩 규칙(src/CLAUDE.md)을 준수하는 설계
- 변경 없는 산출물은 이전 Phase 것 유지

## 완료 조건

- 대표 승인

## 실패/에스컬레이션 조건

- 분석 리스크 대응 불가 시 대표에게 에스컬레이션
- 기술 스택 제약으로 설계 불가 시 보고
