## 입력 (이전 스킬에서 받는 바통)

- PLN-001 요구사항 정의서
- PLN-002 Phase 계획서
- PLN-003 우선순위 목록
- PLN-004 용어 사전
- PLN-005 프로젝트 코드 체계

## 출력 (다음 스킬에 넘기는 바통)

- ANL-001 분석 보고서
- ANL-002 의존관계 맵
- ANL-003 리스크 목록
- ANL-004 기술 스택 결정서

## 필요 권한

- 도구: Read, Grep, Glob, Bash (코드 분석용)
- Sub-Agent: 없음

## 절차

1. 요구사항 정의서와 Phase 계획서 읽기
2. 각 기능의 기술적 실현 가능성 검토
3. 기존 코드/시스템과의 의존관계 분석
4. 영향 범위 파악: 변경 시 영향받는 파일/모듈 식별
5. 리스크 식별: 기술 리스크, 일정 리스크
6. 미결정 사항에 대한 기술적 판단 제시
7. 분석 보고서 작성 및 대표에게 보고

## 의사결정 포인트

- 리스크 "높음" 항목 발견 시 대표에게 별도 보고 (높음)
- 기술 스택 결정: 대표 확인 (보통)

## 체크포인트

- 의존관계 맵 완성 후 중간 보고
- 리스크 식별 완료 후 검토 요청

## 제약 사항

- 코드를 직접 수정하지 않는다 (분석만)
- 확인된 사실과 가정/불확실성을 구분한다
- 분석 대상 코드의 branch 또는 commit을 기록한다
- plan 스킬의 산출물을 입력으로 사용

## 완료 조건

- 기술적 실현 가능성 확인
- 리스크 식별 완료
- 요구사항별 영향 범위 연결

## 실패/에스컬레이션 조건

- 기술적 실현 불가 판단 시 대표에게 에스컬레이션
- 치명적 리스크 발견 시 즉시 보고
